The single most useful thing to know about this exam Candidate write-ups converge on one rule: the correct answer fixes the root cause structurally; the distractors add a probabilistic layer on top of a broken design. When two options both "work", pick the one enforced by code, config, schema, or API parameter over the one enforced by asking the model nicely.

The seven anti-patterns the exam plants as distractors

Nearly every wrong answer in the real exam is one of these dressed up in business language. Learn them as a checklist and you can eliminate two options before you finish reading the stem.

Anti-patternThe tempting wrong answerWhat the exam wants
Prompt-based enforcement"Add a line to the system prompt / CLAUDE.md telling it never to…"A deterministic gate: permission rule, hook, backend validation, schema constraint
Self-reported confidence"Escalate when the model's confidence score drops below 0.7"Deterministic, observable triggers: explicit customer request, policy gap, no progress after N attempts
Batch API in a blocking path"Use the Message Batches API to cut cost 50%"Batch is asynchronous with a 24-hour window — never in a user-facing or pre-merge path
Bigger context window"Load all 400 files into one giant prompt"Focused per-unit passes; attention dilutes long before the window fills
Silent subagent failure"Return an empty result so the coordinator keeps going"Structured error payload the coordinator can act on: what failed, is it retryable, what partial data exists
Unrestricted tool access"Give every agent the full tool catalogue for flexibility"Role-scoped tool assignment — fewer tools, less selection ambiguity, smaller blast radius
Flat agent topology"Let the agents talk to each other to coordinate"Hub-and-spoke: one coordinator owns decomposition, merging, and final resolution

How to use this hub

  1. Day 1–3 — Read. Work through Documentation topic by topic. Do the Q&A drill at the end of each topic before moving on; if you miss one, re-read the section above it rather than pushing forward.
  2. Day 4–6 — Build. Do every Exercise. The browser-checked ones are graded against the exam's rules; the terminal labs make the config behaviour real. Configuration knowledge that you have only read is the knowledge that fails under time pressure.
  3. Day 7 — Sit it timed. Take the Mock Exam in Exam mode: 120 minutes, no feedback until you submit. Aim for 850+ before booking, because a proctored, closed-book environment costs you points a practice run does not.
  4. Day 8 — Review. Re-open the finished exam and read every explanation, including the ones you got right. The "why the others are ruled out" text is where the marginal points live.
  5. Then retake in Study mode with the question order shuffled, to check you learned the principle rather than the answer letter.
